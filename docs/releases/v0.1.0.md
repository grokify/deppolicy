# Release Notes v0.1.0

**Release Date:** 2026-08-29

The initial release: a statically analyzable, default-deny dependency-policy engine. An authored `policy.json` declares which components may directly depend on which others; a scanner produces a `graph.json` of what actually exists; a pure evaluator reports where reality diverges from intent. The model is ecosystem-neutral — Go ships as the first and reference scanner.

## Default-deny with a ratchet

Enforcement doesn't wait for a fully classified ecosystem. Freeze a baseline graph, then:

```bash
deppolicy diff --policy policy.json --baseline baseline-graph.json <roots...>
```

Violations **absent from the baseline** fail (new debt); baselined violations warn (existing debt, classified incrementally via `promote`). From day one, the ecosystem cannot get more coupled accidentally.

## The policy model

- **Components** — declared by policy, not implied by packaging: Go modules, directories within them (*proto-modules*), and by design npm packages, crates, container images, services. Longest-prefix locator resolution; `kind` never affects semantics.
- **Relationships** — explicit `can_depend_on` edges with a required `reason`; **exceptions** are time-bounded with required expiry.
- **Status** — `foundation` (universally consumable; may itself depend only on foundation), `deprecated` (no new dependents), `ungoverned`.
- **Tiers** — archetype-level rules: explicit, non-transitive `mayDependOn` allow-lists (no layer skipping, no same-tier auto-allow) and `mayNotDependOn` deny patterns — the one rule that reaches third-party targets, for constraints like *"an abstraction core must not import provider SDKs."* A deny overrides every allow; the sole escape valve is an unexpired exception.

## Scanning

```bash
deppolicy scan --output graph.json ~/src/org-a ~/src/org-b   # source imports, file:line evidence
deppolicy scan-github org-a org-b                            # go.mod via GitHub API, no cloning
```

Multi-root scans share one component registry so cross-org deep imports resolve to their owning modules; one broken repository never aborts a fleet scan; excluded is never invisible.

## Enforcement surface

- **CLI** — `scan`, `scan-github`, `check`, `diff`, `policy-diff`, `validate`, `promote`, `report`, `export`, `tables`, `ui`
- **Analyzer** — `deppolicy-vet` reports violations at the offending import line, standalone or via `go vet -vettool`
- **GitHub Action** — composite action with `check` and `diff` (ratchet) modes
- **HTML report** — five self-contained pages: summary, filterable findings, component inventory, interactive org-grouped graph, tier structure

## Authoring aids

`promote` proposes relationships for unauthorized observed edges — evidence attached, placeholder reasons that a reviewer must replace — and never writes the policy. `policy-diff` reviews policy changes as architecture changes, flagging removals whose edges are still observed as breaking.
